## 验收

### 1 构建（验收标准 1）

```bash
cd ~/week2-dockerfile
docker build --build-arg HERMES_VERSION=v2026.8.27 -t hermes:v2026.8.27 .
```

> 第一次构建要下载 Python 3.11 和全部依赖，10 分钟上下属正常；之后再构建会命中缓存，只重跑 ⑦ 之后的层，很快。
>
> **想换版本就换 tag 重跑同一条命令**，如 `v2026.8.19`——能装上别的版本，才证明版本号真的参数化了。交作业前务必换一个版本再 build 一次。

### 2 验证版本一致（验收标准 2）

```bash
# 在容器里查 hermes 版本（CMD 会被这里的命令临时覆盖，属于 docker run 的正常用法）
docker run --rm hermes:v2026.8.27 hermes --version
# 预期输出：Hermes Agent v0.20.6（语义化版本）

# 再交叉核对 git tag（应显示你传入的 v2026.8.27）
docker run --rm hermes:v2026.8.27 git -C /usr/local/lib/hermes-agent describe --tags
```

📸 **截图 2**：上面两条命令的输出，和输入的 `v2026.8.27` / Release 页标题 "v0.20.6 (2026.8.27)" 能对上。

### 3 验证容器能启动、进程能跑（验收标准 3）

```bash
# 后台起一个容器：先打印版本，然后保持存活 5 分钟供你检查
docker run -d --name hermes-alive hermes:v2026.8.27 \
  bash -c "hermes --version && sleep 300"

# 确认容器是 Up 状态、没退出
docker ps
```

> 为什么多加 `sleep 300`：`hermes` 不带参数是交互界面，后台（无键盘）模式跑不起来；week3 的 soak 自动对话脚本会取代这里的 `sleep`，变成真正挂着跑对话。本周用 sleep 让你能截到"进程活着"的图即可。

📸 **截图 3**：`docker ps` 显示 `hermes-alive` 状态 `Up`。

![image-20260830083753934](.\assets\image-20260830083753934.png)

### 4 附带验证：镜像确实是"干净"的（无记忆插件）

> 注意方向：week2 要求恰恰是**不装**记忆插件（硬要求 2）。最终工具的流程是"拉干净镜像 → 测试时现装插件 → 测兼容性"，插件预装了反而跑题。所以这里验证的是插件**不在**。对照物就是 week1 截图里的三样东西：Gateway 进程、8420 端口、L0-L3 落库数据——干净镜像里它们全都不应该存在。

```bash
docker run --rm hermes:v2026.8.27 bash -c "\
  echo '=== ① 数据目录：应没有 week1 的 L0-L3 记忆落库数据 ===' && \
  ls -la ~/.hermes/ ; \
  echo '=== ② 搜插件痕迹：应无输出 ===' && \
  find /root /usr/local /opt \( -iname '*tencentdb*' -o -iname '*agent-memory*' -o -iname '*tdai*' \) 2>/dev/null ; \
  echo '=== ③ 记忆 Gateway 端口：应拒绝连接 ===' && \
  { curl -s -m 2 http://127.0.0.1:8420/ && echo '竟然有服务?!'; } || \
  echo 'connection refused → 无 Gateway，镜像干净'"
```

三条都符合预期 → 把这个输出也截一张图（可作为 README 里"已知限制：不含插件"的佐证）。

## 常见报错速查

| 报错（关键词） | 原因 | 解决 |
| --- | --- | --- |
| `permission denied ... /var/run/docker.sock` | 没重启就跑 docker | 重启虚拟机（阶段 1.4） |
| `docker pull` 超时 / `TLS handshake timeout` | 没换源或源失效 | 换源 |
| 构建时 `curl: command not found` |                                       | slim 镜像没 curl，保留那一层 |
| 构建卡在 install.sh 不动了 | 忘了 `--skip-setup --non-interactive` | 检查参数 |
| 容器里 `hermes: command not found` | 安装失败 | 回看构建日志里 install.sh 的报错输出 |
| `invalid reference format` | 镜像 tag 拼写错 | `-t` 和 `docker run` 里的 tag 要完全一致 |
| install.sh 报 sudo 相关错误 | 容器里没有 sudo | 正常现象，脚本会跳过可选项；若缺 ripgrep/ffmpeg 报错 |
